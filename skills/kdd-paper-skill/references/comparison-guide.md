# Comparison guide

For a comparison request, make the user's artifact the unit of analysis.

1. Identify the user's claim, contribution type, current evidence, stage, and
   constraints.
2. Retrieve a small set of comparable KDD papers by problem structure,
   contribution type, evidence need, evaluation setting, and resource limits.
   Use targeted manifest and paper-ID lookups; do not enumerate the full card
   directory for a single request.
3. For each proposed change, connect the artifact location to a separately
   bound source observation. Keep the paper title, exact observation, and direct
   locator together. The locator must support the observation and every
   condition attached to it. Then state a concrete revision or next check, why
   it applies, and an important difference or limit.
4. Give at most three high-priority improvements unless the user asks for a
   different scope. It is valid to find no useful gap.

Do not choose examples by award status or citation count alone. A method paper
should not be compared only with an ADS deployment. A resource paper need not
add a new predictive mechanism. A theory paper need not win an empirical
benchmark.

For an experiment plan, state only what changes the decision: claim,
comparison, unit of analysis, controlled conditions, outcome, and how each
possible result changes the interpretation. A suggested check is not evidence
that the cited paper performed it.
